# Gubots

Equipe local de agentes de IA no Windows: cada bot roda em **Claude Code** (Claude Agent SDK) ou **Codex** (`codex app-server`) com o modelo que você escolher, tem avatar, navegador próprio ao vivo, memória compartilhada e delega tarefas de verdade para os outros.

## Rodar

Requisitos: Windows 11, Node 24+, Google Chrome, `claude` logado (assinatura Claude) e `codex` logado (ChatGPT), e `graphify` no PATH para o grafo. O app usa os logins que já existem; não pede chave de API. O Codex roda pelo binário do pacote `@openai/codex` do projeto (o `codex` global pode estar velho demais para os modelos da conta; o login em `~/.codex` é o mesmo).

```bash
npm install
```

```bash
npm run build
```

Depois abra com duplo clique em `start.vbs`: o servidor sobe sem janelas de terminal e o navegador abre em http://127.0.0.1:8787.

Para desenvolver: `npm run dev` (servidor, reinicia ao salvar) + `npm run dev:web` (UI em http://localhost:5173).

Se já estiver rodando, o `start.vbs` só abre o navegador. Encerrar: botão ⏻ no rodapé da barra lateral (ou `POST /api/quit`). O Chrome de cada bot fecha junto com o servidor (está preso ao processo pai pelo pipe do DevTools) e, por garantia, o boot mata qualquer Chrome que esteja usando os perfis do Gubots, o que evita o erro de perfil travado (exit 21).

### Vigia (religamento automático)

`watchdog.vbs` roda escondido pelo **Agendador de Tarefas do Windows** (tarefa `Gubots`, criada por `install-autostart.ps1`, sem admin): sobe no login e o Agendador confere a cada 5 min se ele ainda está vivo. Rodar pelo Agendador importa: um processo iniciado de dentro de outro app (terminal, Claude, editor) morre junto quando esse app fecha ou se atualiza. A cada 20 s o vigia:
- testa o servidor local; 2 falhas seguidas → mata o node travado e sobe de novo (volta em ~1 min);
- se houver túnel Cloudflare configurado (`data/cloudflared/config.yml`), garante o túnel: sobe o `cloudflared` se ele não estiver rodando e o reinicia se o endereço público falhar 3 vezes seguidas com o servidor ok (volta em ~30 s).

Eventos em `data/watchdog.log`; log do túnel em `data/cloudflared/tunnel.log`. Para desligar o religamento: `Unregister-ScheduledTask -TaskName Gubots` e encerre o `wscript.exe` do vigia. Para reinstalar: `powershell -ExecutionPolicy Bypass -File install-autostart.ps1`.

## Como funciona

| Peça | Onde | O que faz |
|---|---|---|
| Motores | `server/engines.ts` | Claude: um processo vivo por bot+conversa (modo streaming), fechado após 3 min parado (~285 MB cada; reabrir retoma a sessão em ~3-4 s), termina o turno no `end_turn`. Codex: um `app-server` (binário do `@openai/codex` do projeto) por JSON-RPC. Os dois viram o mesmo stream de eventos. |
| Modelos | `GET /api/models` | Lidos das contas em tempo real: `supportedModels()` do Agent SDK e `model/list` do Codex. Nada fixo no código. Raciocínio baixo/médio/alto → `effort` de cada motor. |
| Busca web | `server/hub.ts` | Sempre ligada em todo bot (`WebSearch`/`WebFetch` no Claude, `web_search` live no Codex): a ficha força `web` e, ao iniciar, bots antigos sem web ganham a ferramenta (sessões zeradas). Na ficha a caixa Web fica marcada e travada. |
| MCP próprio | `server/mcp.ts` | Um endpoint HTTP por bot (`/mcp/<bot>`), igual para Claude e Codex: navegador, equipe (`list_agents`, `get_agent`, `delegate_task`) e memória (`remember`, `recall`, `forget`, `graph_query`). |
| Navegador | `server/browser.ts` | Chrome instalado via Playwright, perfil persistente por bot (logins salvos), `domcontentloaded` (nunca espera `load`/`networkidle`), timeouts curtos. Ao vivo na UI via CDP `Page.startScreencast` por WebSocket (~12 fps), com o elemento em foco destacado e "Assumir controle". O Chrome de um bot fecha sozinho após 5 min parado (sem ninguém assistindo e sem tarefa), economizando ~1 GB; os logins ficam no perfil e ele reabre na próxima navegação (~2-4 s). Bloqueia scripts/XHR/iframes de anúncios e rastreadores pelo host (doubleclick, googletagmanager, taboola, criteo...), sem dependência nova; imagens, CSS, fontes e a página principal passam. **Downloads**: arquivo baixado (clique em botão/link, `browser_open` direto na URL do arquivo, blob gerado por XHR + `a[download]`, popup ou nova aba; o perfil do bot tem "abrir PDF externamente", então PDF sempre baixa em vez de abrir no visualizador; depois do clique, espera as chamadas XHR/fetch terminarem, até 15 s) vai para `data/bots/<bot>/downloads/` com o nome sugerido, sem sobrescrever (`nome (1).pdf`); o retorno de `browser_open`/`browser_click`/`browser_type`/`browser_snapshot` traz `download salvo: downloads/<nome>` + caminho completo + link `/api/bots/<bot>/files/downloads/…`. Download lento (> 2 min) aparece no retorno seguinte. |
| Delegação | `server/hub.ts` | `delegate_task` valida a ficha do executor (ferramentas, `login:<domínio>`, `app:<toolkit>`), recusa com sugestão de quem tem, cria a tarefa, roda o executor e devolve o resultado ao solicitante. Guardas: profundidade 3, sem ping-pong (ninguém da cadeia recebe de volta), timeout de 5 min. Fila por bot **e conversa**: cada conversa roda em paralelo, sem esperar o trabalho do mesmo bot em outra; no chat, "trabalhando", passos e o botão parar mostram só o que é daquela conversa. |
| Memória | `server/db.ts`, `server/memory.ts` | Histórico bruto append-only (SQLite + `.md` em `data/memory/raw/`), FTS5. Fatos com bot, data e origem; esquecer = marcar obsoleto; fato obsoleto pode ser apagado de vez na aba Memória ("Apagar", some também da busca). **Estilo caveman fixo**: todo bot (chefe, Claude, Codex, novos; chat e delegação) recebe no system prompt e no perfil (`CLAUDE.md`/`AGENTS.md`, regravados ao iniciar) a regra de respostas extremamente curtas (`STYLE` em `server/hub.ts`). **Regras permanentes** (fatos fixados: tom/formato de resposta, regras gerais) vão sempre no topo do prompt de todo bot (chat, delegação, Claude e Codex), antes dos fatos por busca; fixe/desafixe na aba Memória ("Tornar permanente"), pelo `remember` com `permanent: true` ou deixe o aprendizado automático classificar. Ao fim de cada tarefa, o Haiku resume só aquela tarefa e deduplica. Grafo graphify em lote (botão ou 03:00). |
| Agenda (tarefas agendadas) | `server/schedule.ts`, tela Agenda | Cada agenda tem bot, instrução e quando rodar: **uma vez** (data e hora; depois de rodar com sucesso **sai da Agenda** sozinha — fica arquivada no banco com o histórico; se falhar ou for pulada, continua visível; reativar pede data futura), horário fixo + dias da semana (vazio = todo dia) ou a cada N min (mín. 5), no fuso America/Sao_Paulo. **Lembretes**: todo bot tem a ferramenta `create_reminder(when "AAAA-MM-DD HH:MM", instruction, title?, bot?, email?)`, que cria uma agenda "uma vez" e faz o resultado voltar na mesma conversa em que você pediu ("amanhã 15h me lembra de ligar pro cliente"); devolve a hora agendada e a hora atual para o bot conferir. **Erro passageiro**: se o motor falhar por modelo lotado ("at capacity"), limite de uso (429), 5xx ou rede, a execução agendada tenta de novo sozinha em 2, 5 e 10 min (aviso na conversa); outros erros falham na hora. **Agenda pelos bots**: todo bot (atual ou futuro, sem habilitar nada) também tem `create_schedule(kind once|daily|interval, when?, time?, days?, every_minutes?, instruction, title?, bot?, email?)` para tarefas únicas ou recorrentes direto pelo chat, sem delegar; `list_schedules`; `update_schedule(id, …, paused?)` e `delete_schedule(id)` só nas agendas que o bot executa ou criou. Valida HH:MM, data, intervalo ≥ 5 min e recusa título repetido do mesmo bot; o resultado cai na conversa onde foi pedido. Lembrete "uma vez" perdido num reinício (há mais de 15 min) fica "pulada" e avisa na conversa com o bot. No horário o servidor manda a instrução ao bot como se fosse você, na conversa mais recente com ele (cria uma se não houver). Opcional: o resultado vai também por e-mail pelo Gmail do Composio Connect (`GMAIL_SEND_EMAIL`, chamado pelo servidor). Loop de 30 s, sem dependência nova; o próximo horário é gravado antes de rodar e cada agenda roda uma vez por vez (sem duplicar). Depois de reinício, horário perdido há mais de 15 min vira "pulada" no histórico (não dispara atrasado em massa). **Sem novidades = silêncio**: se o bot responde vazio, só pontuação (ex.: ".") ou "sem novidades", nada vai ao chat (nem a instrução) e nada vai por e-mail; a execução fica no histórico como "sem novidades (silêncio)". Instruções de rotinas de monitoramento pedem "." quando não há nada a reportar. Tela: criar, editar, pausar, excluir, rodar agora e histórico (últimas 20: status, duração, erro, e-mail). API `/api/schedules`. |
| Acessos | `server/hub.ts` | Todo bot recebe no prompt um bloco "Seus acessos" gerado do que está marcado na ficha (navegador e sites com login, busca na web, arquivos, terminal, apps do Composio) e como usar cada um. No Codex, os recursos próprios do app (navegador/computer use, plugins, modo código, subagentes) ficam desligados para ele usar os do Gubots; no Claude, as ferramentas MCP do Gubots e do Composio são sempre carregadas (nunca escondidas atrás de busca). |
| Missão | `server/mission.ts`, barra lateral → Missões | Grupo visível orquestrado pelo chefe (Jarvis). Criar: título + problema + 2 a 6 bots (o chefe entra sempre). Ele monta o plano e chama **um bot por vez com @** e a instrução do passo; o bot responde no grupo como mensagem dele (nome, ícone, arquivos) e o chefe revisa à vista e chama o próximo (pode mudar a ordem). Bots **não se acordam sozinhos**: só fala quem o chefe ou você marcar com @ (no campo, botões de @ múltiplo); `delegate_task` é bloqueado na missão (nada de cartão escondido). **Contexto compartilhado**: todo bot chamado recebe o problema, os membros, o histórico da missão (completo na primeira vez; depois só o novo desde a última fala dele, já que a sessão guarda o resto) e o pedido do passo; corte inteligente mantém o problema e as mensagens recentes inteiras, encurta as antigas e omite o meio se passar do orçamento. Travas: 15 passos por mensagem sua (sua mensagem zera; contador "passo N/15" no topo), parar mata a fila. "Encerrar missão": o chefe posta a síntese final e ela vai para a memória (sem .md). |
| Sessões | `server/hub.ts` | Uma sessão do motor por bot + conversa (o bot lembra o que foi dito). Mudar a ficha de um bot **Claude** (apps, ferramentas, modelo) mantém a sessão: o processo reabre com a config nova e retoma a conversa. Codex (config fixa na thread) e troca de motor começam sessão nova; nesse caso, e se a sessão se perder, o bot recebe as últimas mensagens da conversa em texto (até ~12 mil caracteres) para não perder o contexto. |
| Perfil | `data/bots/<id>/CLAUDE.md` e `AGENTS.md` | Único contexto sempre carregado. O chefe recebe também o roster (1 linha por bot). |
| UI | `web/` | Vite + React + Tailwind + shadcn/ui. **Visual "Noir"**: fundo preto puro, superfícies de vidro escuro, acento em gradiente azul → ciano, fonte Geist, botões redondos de vidro e animações suaves (desligáveis; respeita `prefers-reduced-motion`). **Feito para o celular**: áreas seguras do iPhone, campos com 16 px (sem zoom), gaveta lateral que abre deslizando o dedo da esquerda para a direita (em qualquer ponto da tela) e fecha arrastando, **botão voltar do Android navega dentro do app** (fecha gaveta, painel, diálogo ou volta à tela anterior; na tela inicial avisa e só sai no segundo toque), diálogos viram folha que sobe do rodapé, cabeçalho com a pílula do bot no centro (toque troca modelo e raciocínio) e, à direita, lupa (busca), navegador e engrenagem que abre as configurações do bot (de qualquer tela), tela inicial com orb animado e chips em duas linhas, composer em pílula com botão principal que vira microfone, enviar ou parar, e ditado com ondas pelo volume da voz e brilho vermelho no rodapé. **Anexos** no chat: botão +, colar, ou arrastar o arquivo para qualquer ponto da conversa (aparece "Solte para anexar" e ele entra como anexo no composer; solto fora do chat, o navegador não abre o arquivo) — até 10 arquivos de 25 MB. Imagens e PDF chegam ao Claude como conteúdo nativo; ao Codex, imagens como imagem; textos e código entram no texto; outros formatos ficam salvos em `data/uploads/<conversa>/` e o bot recebe o caminho. **Busca na conversa**: lupa no cabeçalho (no celular, no menu "…") ou Ctrl F abre a barra que destaca as ocorrências no texto, mostra "2 de 7" e navega com Enter/Shift Enter ou as setas; Esc fecha. **Delegação como conversa**: quando um bot pede ajuda, aparece a mensagem dele "@Executor objetivo" (rodapé com #tarefa, status e tempo, leva à aba Tarefas), a pílula "Executor entrou na conversa", a resposta do executor e "Executor saiu · concluiu em 1:08". **Responder trecho**: selecione parte de uma resposta do bot e toque em "Responder"; o trecho vira citação acima do campo (X remove) e vai no começo da mensagem como `> trecho`, então o bot responde sobre ele; na conversa a citação aparece acima do seu balão. **Chat em balões** (você à direita, bot à esquerda com avatar, nome, modelo e hora; balão "digitando" enquanto trabalha), cabeçalho com modelo e o que o bot está fazendo agora, boas-vindas com sugestões, markdown (código com copiar; **tabelas** com barra de linhas e "Copiar p/ planilha" (TSV), cabeçalho fixo, zebra, ícones no cabeçalho por assunto (status, preço, data, nome, link…), colunas numéricas alinhadas à direita, palavras nunca quebradas no meio (1ª coluna sem quebra; no celular a tabela rola na horizontal) e status virando ícone colorido — ✅/sim/pronto, ❌/não/erro, ⚠️/parcial, ⏳/pendente, "-" esmaecido), streaming com "pensando…" e chips das ferramentas, copiar/tentar de novo, cartões de tarefa, composer com troca rápida de modelo e raciocínio, microfone para ditar (grava, e ao parar o Whisper transcreve e insere o texto uma vez, depois do que já estava digitado; mostra "Gravando" com tempo e "Transcrevendo…"). **Navegador do bot**: ícone de globo no cabeçalho abre/minimiza o painel ao vivo e mostra um ponto vermelho piscando quando está em uso; o painel pode ser redimensionado e tem "Assumir controle"; no celular, em "Assumir controle", tocar num campo do site já abre o teclado e o que você digita vai ao vivo, letra por letra (apagar manda Backspace, Enter confirma); também dá zoom com pinça (dois dedos), arrastar com um dedo quando ampliado e toque duplo para 2,5x/1x (botão "1x" volta; arrastar/pinçar não vira clique no site); com página aberta, o botão ⛶ na barra de endereço põe o navegador em tela cheia (API nativa no PC/Android, modo fixo no iPhone; Assumir/Devolver dentro dela; Esc ou ⛶ sai). **Bots** (cartões com as ações numa linha só: Conversar ocupa o espaço e Computador/Editar viram ícones no celular; "Novo bot" na linha do título), **Tarefas** ("Precisa de você" com botões na linha: Passar ao X, Tentar de novo, Excluir; no detalhe, bloco "Como resolver" com o motivo e as opções, mais Abrir conversa; tarefa parada pode ser excluída, em andamento só cancelada; cadeia de delegação), **Memória** (fatos com origem, grafo, histórico, inbox, Obsidian) e **Configurações** (geral, motores, navegador, integrações, memória, celular e acesso, sistema). **Barra lateral** em camadas: marca no topo, Equipe com status ao vivo (cada bot é também a conversa com ele: destaca a aberta, mostra não lidas e a hora da última mensagem; o menu do bot tem Apagar conversa) e, no rodapé, a navegação principal numa linha de ícones (Conversas, Bots com ícone de robô, Tarefas e Memória, com contadores) acima do cartão do usuário com Configurações. Paleta Ctrl+K; Ctrl+B recolhe a barra lateral; Ctrl+, abre Configurações; Ctrl+Shift+O abre nova conversa. **Respostas ricas** (`web/src/components/RichBlocks.tsx`, guia no system prompt de todo bot): blocos ```` ```opcoes ```` (botões de resposta rápida; um toque responde), ```` ```formulario ```` (JSON com campos já preenchidos pelo bot; enviar responde "- Rótulo: valor"), ```` ```aprovar ```` (obrigatório antes de enviar/postar/apagar/pagar: Aprovar, Editar ou Cancelar), ```` ```grafico ```` (barras ou linha em SVG próprio, valor ao tocar) e ```` ```linha-do-tempo ```` ("dd/mm/aaaa | texto", datas futuras em destaque); avisos coloridos com `> [!aviso]`/`[!ok]`/`[!erro]`/`[!dica]`; checklist `- [ ]` clicável com barra de progresso, salva na mensagem (`POST /api/messages/:id/check`); link sozinho na linha vira cartão de prévia (`GET /api/preview`, só endereços públicos, cache 6 h); tabelas ordenam pelo cabeçalho, filtram (6+ linhas) e baixam CSV. Botões e formulários ficam ativos até você responder. **Reações**: bots podem reagir com emoji às mensagens (ferramenta MCP `react`; padrão: a última sua na conversa; uma reação por bot, emoji vazio tira). Aparece como no WhatsApp: emoji com o avatar de quem reagiu, colado no balão. **Cor do avatar**: na ficha do bot, abaixo dos avatares, escolha a cor (original, paleta ou "+" para qualquer cor); fica salva junto do avatar (`atlas#a855f7`), pinta o corpo, ajusta os olhos ao contraste e o brilho de "pensando" (o ícone da notificação usa o desenho original). **Avatares**: 15 opções (jarvis, atlas, lira, nova, orion, vega, terra, sol, flor, hexa, cubo, estrela, fantasma, capsula, coracao; PNG de cada um em `web/public/avatars/` para as notificações). Pensando, o avatar pula e estica, balança, olha para os lados, pisca, brilha na cor dele e mostra um balão "…" (barra lateral, cabeçalho e a linha "trabalhando" do chat; mensagens antigas ficam paradas); respeita animações desligadas. **Arquivos no chat**: imagens, PDF, DOCX e textos (anexos seus e links `/api/bots/<id>/files/…` nas respostas) viram cartões com miniatura, botão Expandir (tela cheia com o documento inteiro; Esc, X ou voltar fecham) e Baixar; outros tipos mostram o ícone e baixam. PDF via `pdfjs-dist` e DOCX via `docx-preview`, carregados só quando aparece um arquivo desses (`web/src/components/FilePreview.tsx`). **Design e docs** (ferramenta da ficha do bot; ligada no Pixel): skills oficiais da Anthropic (`anthropics/skills`: pptx, docx, xlsx, pdf, frontend-design, canvas-design, algorithmic-art, theme-factory, web-artifacts-builder, slack-gif-creator) em `data/skills`, instaladas por `npm run design:setup` (também põe pptxgenjs/docx/sharp em `data/node_modules` e markitdown/python-pptx/python-docx/openpyxl no Python). Ao rodar, o Gubots liga `data/skills` na pasta do bot (`.agents/skills` para Codex, `.claude/skills` para Claude; desligar só tira a ligação). Sem LibreOffice: `office_to_pdf` e a prévia do chat convertem pptx/xlsx/docx pelo Office do PC (COM oculto, `server/office.ts`, cache em `data/cache/office`, `GET /api/office-pdf`). Prévia no chat: HTML (mockup, protótipo, animação) roda num iframe isolado; PPTX/XLSX aparecem como PDF. **Cofre de senhas** (`server/vault.ts`, Configurações → Senhas): credenciais criptografadas (AES-256-GCM) em `data/vault.json` com chave em `data/vault.key`; a API nunca devolve o valor. Bots com navegador têm `list_secrets`, `fill_secret` (digita usuário e senha só em página https do site da credencial, sem ver) e `request_secret` (cartão seguro no chat; o usuário digita, escolhe se libera só para aquele bot ou para todos, e a ferramenta continua sozinha). `remember` e a memória automática recusam texto com senha. **Pedir para assumir**: `request_takeover` só depois de tentar sozinho (2FA, CAPTCHA, Cloudflare, passkey): cartão + notificação; você abre o navegador do bot, resolve e toca "Pronto, continue" (espera até 12 min). **Subagentes**: `spawn_subagent` cria ajudante temporário (mesmo modelo, sessão descartável, sem navegador nem MCP), vários em paralelo; no limite usa a reserva. **Arquivos da conversa**: botão de pasta no cabeçalho com contador (no celular, no menu "…" junto com Buscar, para o nome do bot caber) abre todos os arquivos da conversa (seus anexos e os dos bots) com prévia e lixeira para apagar de vez (`POST /api/files/delete`, só dentro da pasta do bot ou dos anexos; perfis do bot protegidos); o cartão na mensagem fica marcado "apagado". **Quedas no meio**: o processo do Claude parado há 3 min é fechado para poupar memória, mas nunca durante um trabalho (antes, tarefa de mais de 3 min morria com "processo do Claude encerrou"). Se o processo do Claude ou o app-server do Codex cair no meio, o Gubots reabre, retoma a sessão e pede para continuar de onde parou (uma vez). **Modelo reserva**: se o motor do bot bater no limite (modelo lotado, cota, 429/529/503, overloaded), o mesmo pedido segue no outro motor com o histórico recente da conversa: Codex → Claude Opus 5.5; Claude → Codex GPT-6.1-Sol (todo bot). Por 15 min aquele modelo vai direto para a reserva. A resposta mostra o modelo usado com "· reserva"; a sessão da reserva fica separada (`bot#motor`). **Complemento**: mensagem nova enquanto o bot ainda trabalha no seu pedido não vira tarefa nova: entra no mesmo trabalho. Codex: vai direto no turno atual (`turn/steer`), sem parar. Claude: o turno pausa e retoma na mesma sessão com o complemento (o que já fez fica no histórico). Tarefas delegadas rodando na conversa continuam indo para a fila. **Na fila**: pedido feito enquanto o bot ainda trabalha na mesma conversa espera a vez (não interrompe o atual); acima do campo aparece "Na fila (n)" com o texto de cada pedido (e tarefas delegadas esperando) e o X tira da fila antes de rodar (`DELETE /api/queue/:id`). **Novas mensagens**: divisória azul acima da 1ª resposta nova (não lida ao abrir a conversa, ou depois do seu último pedido); a tela segue o fim só até essa divisória chegar ao topo e depois fica parada enquanto a resposta chega, para dar tempo de ler (seta ↓ leva ao fim). **Não lidas**: quando um bot responde e você não está olhando aquela conversa, aparece um selo vermelho com o número de respostas no bot (Equipe), no ícone de Conversas, no botão de menu, no título da aba e no ícone do app (onde o sistema suporta); abrir a conversa zera. O "lido até" fica no servidor (`readTs` da conversa), então vale em todos os aparelhos e conta o que chegou com o app fechado. **Memória automática**: depois de cada pedido seu no chat, o Haiku extrai o que é durável (preferências, regras, decisões, prazos, contatos) e guarda como fato com origem; e todo pedido já vai para o bot com as regras permanentes no topo, mais os fatos ligados a ele e os mais recentes, para seguir sempre o que você quer. **Notificações push** (Configurações → Geral → Notificações): quando um pedido seu termina, o celular recebe a notificação mesmo com o app fechado, como no WhatsApp: foto do bot, ícone do Gubots na barra de status, começo da resposta, agrupadas por conversa ("Jarvis · 3 mensagens") e tocar abre a conversa; com o app aberto e na frente só toca um aviso curto. Web Push padrão (VAPID + aes128gcm) feito com `node:crypto`, sem dependência; chaves e aparelhos ficam em `data/push.json`; "Ativar aqui" inscreve o aparelho e "Testar" manda uma de teste. Subtarefas entre bots não notificam. PWA instalável (ícone: avatar branco do chefe sobre fundo preto; ícones e manifest sem cache longo — só `/assets/` com hash é imutável). |

Dados ficam em `data/` (banco, perfis do Chrome, workspaces dos bots, `memory/`). O vault do Obsidian é a própria pasta `data/memory/`.

**Arquivos gerados pelos bots** (PDF, DOCX etc.) baixam pelo próprio app, no PC ou no celular: o bot responde com `[nome](/api/bots/<id>/files/<caminho relativo>)` e o link baixa o arquivo (com login, só dentro de `data/bots/<id>/`). Caminhos locais `C:\…\data\bots\<id>\…` citados no chat também viram link de download automaticamente.

## Bot de manutenção (opcional)

Um bot com `workdir` apontando para a pasta do Gubots e as ferramentas `files` + `shell` vira o mantenedor do app: você pede pelo próprio chat ("adicione X na tela de bots") e ele edita o código, roda `npm run check`/`npm test`, publica (`npm run build`; mudanças no servidor via ferramenta `restart_gubots`, que reinicia sozinho depois da resposta), atualiza o README e faz commit no git local (`git revert HEAD` desfaz). As regras dele estão em `CLAUDE.md`. As abas abertas mostram "O Gubots foi atualizado · Recarregar" quando há build novo.

## Configuração opcional (`.env`)

Copie `.env.example` para `.env`.

As chaves também podem ser coladas em Configurações → Integrações (ficam em `data/settings.json`; a UI só mostra os 4 últimos caracteres).

- `COMPOSIO_API_KEY` (ou Configurações → Integrações): apps via Composio. **Chave `ck_` (Composio Connect, conta "For You")**: o Gubots lê os apps conectados na conta (Gmail, Calendar, GitHub…) e cada bot ganha caixas de seleção na ficha; o bot recebe um MCP `composio` filtrado pelo Gubots (`/mcp/<bot>/composio`) que só executa ferramentas dos apps marcados, bloqueia o resto com a dica de qual bot tem o app (o chefe então delega) e esconde as ferramentas que rodam código arbitrário (remote bash/workbench). Conectar apps novos: no painel do Composio. Chave de projeto `ak_`: sessão Tool Router por bot com os toolkits escolhidos na busca.
- **Ditado por voz** (`server/stt.ts`, `POST /api/stt`, mesma autenticação das outras rotas): **modo misto**: enquanto você fala, a Web Speech API do navegador (pt-BR, resultados parciais) mostra o texto em tempo real no campo; ao parar, o parcial entra no campo e o motor configurado transcreve o áudio inteiro e o substitui ("Refinando…"; se você editou nesse meio-tempo, nada é trocado). Sem Web Speech (ex.: Safari/iOS) ou se ela falhar: só a transcrição ao parar. Se o servidor falhar, fica o texto do tempo real. Liga/desliga por aparelho em Configurações → Ditado por voz (padrão ligado). o navegador grava com MediaRecorder (webm/opus no Chrome/Android, mp4 no Safari/iOS), converte para WAV 16 kHz mono e envia; o servidor transcreve em pt-BR e devolve o texto. Padrão: **Whisper local** via `@huggingface/transformers` (onnxruntime, sem chave e sem Python; modelo `whisper-small` q8, ~250 MB, baixado na 1ª vez em `data/models/`, carregado quando você começa a gravar e liberado após 10 min parado). Em Configurações → Integrações → Ditado por voz dá para trocar o modelo (Base, Small, Turbo) ou usar a API da OpenAI (`gpt-4o-transcribe`, chave salva no campo da tela; evite `OPENAI_API_KEY` no `.env` para não mudar a conta do Codex) ou do ElevenLabs (`ELEVENLABS_API_KEY`). O áudio fica só em memória; limite de ~5 min por ditado (12 MB); silêncio volta vazio. Se o navegador não decodificar o áudio, o servidor usa o `ffmpeg` do PC, se houver. **Groq (ao vivo)**: motor de ditado com Whisper large-v3 pela API do Groq (chave em Configurações → Integrações; plano grátis); enquanto você fala, o áudio gravado até ali vai a cada ~3,5 s (`POST /api/stt?partial=1`, sem refino) e o texto aparece ao vivo, inclusive no iPhone; ao parar, sai a transcrição final refinada. **Refino com IA** (Configurações → Ditado por voz → "Corrigir a transcrição com IA", ligado por padrão): depois do Whisper, o Claude Haiku corrige pontuação, erros e nomes (glossário com os bots, seu nome e termos do dia a dia + últimas mensagens da conversa) sem mudar o sentido; processo aquecido ao começar a gravar (~1 s); travas devolvem o original se a resposta fugir do tamanho; na OpenAI o glossário também vai como `prompt`.
- `HOST`, `PORT`, `GUBOTS_HEADED=1` (Chrome com janela visível).
- `GUBOTS_ADBLOCK=0`: desliga o bloqueio de anúncios/rastreadores (ex.: se um "Entrar com Facebook" em site de terceiros quebrar, porque ele usa `connect.facebook.net`).

## Acesso de fora do PC (celular, outro computador)

Opcional. Endereço público via Cloudflare Tunnel: crie um túnel no painel da Cloudflare (Networking → Tunnels) com uma rota do seu domínio para `http://127.0.0.1:8787`, ponha a credencial e o `config.yml` em `data/cloudflared/`, troque `PUBLIC_URL` no `watchdog.vbs` e `GUBOTS_PUBLIC_URL` no `.env`. O conector `cloudflared` é do próprio Gubots: a credencial do túnel fica em `data/cloudflared/` (fora do git) e quem o mantém no ar é o vigia (abaixo).

- Fora do PC, o app pede **login só com senha**. A sessão é um cookie HttpOnly e Secure, vale 30 dias, e 5 erros seguidos bloqueiam o IP por 5 minutos.
- No próprio PC (http://127.0.0.1:8787) não pede senha.
- A senha fica só como hash scrypt em `data/settings.json`. Para trocar: Configurações → Celular e acesso, ou `POST /api/password`. Trocar a senha derruba todas as sessões.
- O endpoint MCP (`/mcp/*`) nunca fica aberto: exige o token interno de `data/token.txt`.
- Conexão ao vivo (WebSocket `/ws`): o servidor manda um ping a cada 25 s, porque o Cloudflare derruba conexão ociosa, e fecha o cliente que não responde ao ping/pong (isso também para o screencast dele). A UI dá a conexão por morta após 60 s sem nada e reabre na hora. Também reabre ao voltar para a aba ou para a rede. O aviso "Sem conexão" só aparece se a queda passar de 4 s.
- No celular, abra o endereço, entre com a senha e use "Adicionar à tela inicial" (PWA). O microfone funciona porque o endereço é HTTPS.
- Cache: o service worker é registrado com a versão do build no URL (`/sw.js?v=…`), então nem a Cloudflare nem o navegador seguram uma versão velha.
- Alternativa privada: Tailscale (`tailscale serve --bg 8787`), com o mesmo login.

## Testes

```bash
npm test
```

Testes de fumaça: memória, delegação (ficha, recusa com sugestão, ping-pong), navegador (abrir, snapshot com refs, clique), bloqueio de anúncios e listagem de modelos das contas. `GUBOTS_SKIP_LIVE=1` pula os que precisam de Chrome e logins. `npm run check` roda o TypeScript do servidor e da UI.

## Limitações conhecidas

- O microfone precisa de HTTPS no celular (túnel Cloudflare ou Tailscale serve resolvem). A transcrição local leva alguns segundos no CPU (≈5 s para 10 s de fala com o Small).
- `graph_query` usa `graphify query --budget` pela linha de comando, não o servidor `--mcp` do graphify.
- O grafo usa o backend `claude-cli` do graphify (assinatura Claude via `claude -p`).
